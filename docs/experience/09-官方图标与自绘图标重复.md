# 09 · 官方补了图标之后，我们补的那枚就成了重复

- 日期：2026-11-15
- 类别：跟随官方 / 视觉一致性

## 症状

用户截图指出顶栏两枚 chip 前面「图标认不出来」，怀疑「插件的历史图标和更新的图标冲突」。
放大 4 倍看：`▢ 子智能体 (3) ⟳`、`▣ 后台任务 (2) ⟳` —— 一枚 chip 前面挤着两个 14px 图标。

## 根因

两件事叠在一起：

1. **我们自绘的图标当年是对的**：早期官方那两枚 trigger 只有文字（README 里也写着「原生缺的补上」），
   插件用 `::before + mask` 补了「文件夹+双竖杠」（`SUBAGENT_SVG`）与「`>_` 方框」（`JOBS_SVG`）。
2. **官方后来自己加了图标**：0.2.2-rc.3 的 `dsh-client-ui-subagent` / `-jobs` 里，
   trigger 的 `span.activitySlot`（14×14）已经渲染 `IconUsersOutlineRegular` /
   `IconLayersOutlineRegular`，运行中的 `StateDot` 也在同一格里。
3. **我们还在挪它的子节点**：为了「把运行圆点从图标与文字之间挪到统计数之后」，测量代码把
   **无文字的子节点**标成 `data-bst-chip-dot` 并 `order:1` —— 那个「无文字子节点」就是整块
   `activitySlot`。于是官方图标被挪到末尾，头部只剩我们的自绘图标 → 头尾各一枚。

## 证据（可复跑）

```js
// 页面里 dump 一枚 chip 的真实子节点（0.2.2-rc.3，装饰后）
[...btn.childNodes].map(n => ({ t: n.tagName, cls: n.className, data: [...n.attributes].map(a => a.name) }))
// 修前：span.IRdzoW_activitySlot[data-bst-chip-dot] · span.IRdzoW_count[data-bst-chip-label] · span.bst-chip-count
//       且 getComputedStyle(activitySlot).order === '1'
// 修后：span.IRdzoW_activitySlot（无 data 标记）· span.IRdzoW_count · span.bst-chip-count，order 全 0
```

官方源码位置：`node_modules/@deepseek-ai/dsh-client-ui-subagent/lib/client.js`
（`activitySlot` + `IconUsersOutlineRegular,{size:14}`）、`dsh-client-ui-jobs`
（`activitySlot` + `IconLayersOutlineRegular,{size:14}` + `StateDot`）。

## 同一天的第二处：面包屑的子智能体级

面包屑里同样的毛病，只是更隐蔽：子智能体级用的是手抄 SVG（`SUBAGENT_SVG`），而且 **stroke
被手调成 1.5**（注释写着「1 在这条长轮廓上显得细」）。同一行另外两级是官方组件，于是三级并排
时只有子智能体那级偏粗 —— 同一个「自己调过的重量」。

**第一次改错了语义**：手抄的图形名是 `icon-workspace-tree-outline`，我就照着它换成了
`IconWorkspaceTreeOutlineRegular`。结果 16px 下它画出来像一张小卡片，所有者直接指出来
「三级面包屑的子智能体的图标不对」。查官方用量才看清归属：

| 图标 | 官方用在 |
| --- | --- |
| `IconWorkspaceTreeOutline` | `dsh-client-ui-workspace`（侧栏的**工作区树**） |
| `IconUsersOutline` | `dsh-client-ui-subagent`（**顶栏那枚子智能体 chip**）、agent-team、chat、tool |

所以正确的一枚是 `IconUsersOutlineRegular` —— 与 chip 同源、与「子智能体」这个概念的官方表述
一致。最终：

```js
const CrumbSubagentIcon = IconUsersOutlineRegular || IconQueueOutlineRegular
const CrumbSwitchIcon = IconChevronsUpDownOutlineRegular || IconChevronDownOutlineRegular
```

顺带删掉 `.bst-glyph`（只为包手抄 svg 而存在的包装层及其样式）。`check:instance` 的
「primitives 导出」期望值是从 `require(...)` 的解构里抽的，所以这项自动从 12/12 变 14/14 ——
官方哪天删了这两枚图标，门会先红。

**教训**：手抄代码里的「图形文件名」只是抄写来源，不是语义判据。挑图标要查**官方拿它表达什么**
（哪个包在用、用在哪个概念上），而不是同名就照搬。

## 结论

- **图标一律用官方的**：`chipGlyph('sub'|'jobs')`、`JOBS_SVG`、`SUBAGENT_SVG`、`SWITCHER_SVG`
  全部删除；chip 用官方自带的 `activitySlot` 图标，面包屑三级用
  `IconFolderCloseRegular` / `IconQueueOutlineRegular` / `IconWorkspaceTreeOutlineRegular`，
  标题态父级用 `IconChevronsUpDownOutlineRegular`。
- **不要挪官方的子节点**：`data-bst-chip-dot` 与 `order:1/2` 删除，chip 回到官方顺序
  `activitySlot · 文字 · (N) · 箭头`。
- 一般化：凡是「官方缺 X，我们补 X」的补丁，都要在升级对账里**重新确认官方是不是已经不缺了**。
  补丁本身不会报错，它只会变成第二份重复 —— `check:instance` 现在既核对 chip 是否自带图标，
  也核对面包屑用到的那几枚 primitives 导出还在，官方换图标时先红，而不是等用户截图。
