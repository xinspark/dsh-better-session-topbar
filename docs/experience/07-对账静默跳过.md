# 07 · 对账脚本的「未安装跳过」把假绿藏了三个月

- 日期：2026-11-15
- 类别：门 / 升级对账

## 症状

`npm run check:instance` 一直报 18/18 PASS，但「chip 文案关键字（8 语言）」那一行末尾始终带着
`未安装跳过：team`。也就是说：**智能体团队那枚 chip 的契约，从来没有在这台机器上被核对过**，
而 PASS 的结论看起来和核对过一样。

同一天还发现：agent-team 的包名在 0.2.2-rc.3 已经从 `dsh-experimental-client-ui-agent-team`
改成 `dsh-client-ui-agent-team`，那枚 chip 也已被官方搬出顶栏（改挂
`conversation.session.header.actions.subagent.footer` 渲染任务板）。

## 根因

两件事叠在一起：

1. 对账脚本按**硬编码包路径**读官方包，包改名后 `asar.read()` 返回 `null`；
2. 脚本把 `null` 当成「该插件没装」，于是走进 `skippedChips` 分支——**跳过不计失败**。

「没装」与「找不到」在代码里是同一个 `''`，于是改名（契约变了，必须复核）被记成了缺失
（这台机器没这功能，不关我们的事）。

## 证据（可复跑）

```sh
node tools/check-instance.mjs            # 改前：… 均在官方包里命中；未安装跳过：team
node .scratch/list-pkgs.mjs team         # dsh-client-ui-agent-team / dsh-agent-team / dsh-tool-agent-team
```

`dsh-experimental-client-ui-agent-team` 在该实例的 asar 里**不存在**，而插件源码里的
`CHIP_SELECTORS.team = '[data-team-action] button'` 在新包里也搜不到（新包用的是
`data-team-panel` / `data-team-task` / `data-team-command`）。

## 结论与做法

- **路径要能多候选**：team 现在两条路径都试（新名优先，旧名兜底），老实例照样能核。
- **跳过必须是「可解释的结论」，不能是空白的通过**：现在该行会写
  `未安装跳过：team（已移出顶栏）`，并且新增一条独立的「chip 结构锚点」项，把
  「它搬到哪了」当作契约核对的一部分。
- 一般化：对账项里凡是有 `skip` 分支的，跳过理由必须带上**判据**（包不在？还是符号不在？），
  否则下次改名依旧会被写成「没装」。
